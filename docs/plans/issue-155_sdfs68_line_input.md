# SDFS/68 行入力改善計画

## 対象

- Issue: #155
- 親Issue: #137
- 関連: #153, #150, #149, #138, #136, #130, #82

## 背景

SDFS/68 V1.2は `DIR`、`LOAD`、`RUN addr`、`RUN filename`、`EXIT` まで揃い、実機上でも小さいDOSらしく使えるようになった。
一方で行入力はROMモニタより最低限で、BS/DELを押したときに内部バッファだけ戻り、画面上の文字が消えない。

手入力での使い勝手に効くため、`TYPE` 実装前の仕上げとして行入力をROMモニタ相当に寄せる。

## 方針

- BS / DELで入力中の1文字を削除する。
- 行頭BS / DELは無視する。
- 画面上も1文字消えるように端末へ消去シーケンスを返す。
- SDFS/68は `MIKBUG_INCH` を使っており入力文字が先にechoされるため、BSとDELで補正出力を分ける。
  - BSは既にechoされたBSでカーソルが戻るため、追加で `SPACE` + `BS` を出す。
  - DELはechoされてもカーソル移動しない端末があるため、追加で `BS` + `SPACE` + `BS` を出す。
- 小文字コマンドと小文字ファイル名の扱いをテストで固定する。
- 長すぎる入力でバッファを壊さず、次のコマンドへ復帰できることを確認する。

## 検証方針

- `DIRX` からBSで `DIR` に修正して実行できること。
- `DIRX` からDELで `DIR` に修正して実行できること。
- 行頭BS / DELを押してもSDFS/68起動や次のコマンドが壊れないこと。
- `run hello.s` でS-Recordファイルを実行できること。
- 長すぎる入力後に `?` を表示し、次の `DIR` が動くこと。
- 既存の `DIR` / `LOAD` / `RUN` / `EXIT` の回帰テストを維持すること。

## 対象外

- 入力履歴
- カーソル左右移動
- 行途中編集
- Ctrl-Uなどの行削除
- `TYPE filename`
